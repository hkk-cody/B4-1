# 수정 및 검증 결과

2026-09-06, OrbStack `24.04ubuntu`에서 수정 후 검증했다. 이전 검토의 미완료 상태는 아래 결과로 갱신한다. 최종 제출 문서는 [수행 내역서](../submission.md), 재현 가능한 원본 출력은 [evidence](../evidence/)를 참고한다.

| 발견한 문제 | 수정 및 확인 |
| --- | --- |
| 모니터링 대상이 `agent_app.py`로 고정됨 | `/proc/*/cmdline`의 첫 실행 인자로 ARM64/x86 바이너리 또는 Python 앱을 찾음. 실제 앱과 앱 종료 상태 모두 검사 |
| `/proc/PID/exe`를 일반 계정에서 읽지 못함 | 실행 중 추가 발견. ptrace/그룹 조건에 영향을 받는 exe 링크 대신 argv[0] 비교. sudo 부모 명령은 제외 |
| 앱 배치가 현재 디렉토리에 의존하고 `mv`로 원본 제거 | 스크립트 경로를 기준으로 아키텍처 선택, 원본 보존 복사, 설치 재실행 통과 |
| 관제 스크립트 복사 시 실행 중간 파일 노출 가능 | 새 파일에 설치·문법 검사 후 원자적 이름 변경 |
| SSH 캡처가 22 LISTEN | 현재 20022 LISTEN과 최종 설정 확인. Ubuntu 24.04 socket 재생성 처리, 일반 계정 성공/root 거부 실증 |
| 상위 홈 디렉토리 진입 불가 | common에 홈 통과 권한만 부여. QA 업로드 및 dev 수정으로 검증 |
| 디렉토리의 root 소유 및 ACL 누락 | 역할별 소유 그룹, 2770, access/default ACL. QA의 키·로그 접근 거부 검증 |
| 과제 키 경로와 바이너리 기대 경로 불일치 | 로그인 환경은 t_secret.key, secret.key 링크, 실행 래퍼에서 앱 프로세스만 디렉토리로 변환. Boot 5단계 통과 |
| 방화벽 조회 실패를 비활성으로 오판 | ufw status 하나만 sudo 허용. 조회 실패와 비활성을 별도 경고, cron에서도 active 확인 |
| 현재 파일 포함 로그 11개 | 현재 파일 + 회전본 9개. 실제 10MiB 크기로 회전·개수·경계 검사 |
| 로그가 제한을 넘은 다음 회전 | 다음 줄을 쓸 때 초과하는지 미리 계산 |
| 동시 실행·리소스 파싱 취약성 | flock 사용, /proc/stat 1초 측정, 숫자 검증, C 로케일 |
| report의 잘못된 줄을 0으로 처리 | 로그 형식 검증 후 계산, 잘못된 시간 범위 거부, 정상/빈 결과 검사 |
| cron과 제출 증거 부재 | agent-admin 매분 등록, 자동 실행 이력과 실제 로그 증가, 종합 증거 추가 |

## 검증 범위

필수 요구사항과 보너스 1을 검증했다. 보너스 2는 미선택이다. ARM64 Ubuntu에서 수행했으며 x86 실행은 미검증이다. 방화벽 active는 실제 명령으로, inactive/조회 오류 분기는 대체 응답으로 검증했다.

키 경로의 원문과 바이너리 차이는 실행 래퍼로 처리했고 [제출 문서](../submission.md)에 명시했다. 검증 당시 앱은 일반 사용자 임시 systemd 서비스로 실행했으며 VM 재부팅 뒤 자동 시작하도록 설정한 것은 아니다.

제출 문서, 소스 및 증거를 Git으로 관리한다. 최신 반영 여부는 로컬 `git status`와 GitHub 커밋 내역에서 확인한다.
